Legend for the `W3S` marks used below: **W3S-style** = a W3Schools convention that the standard does not require (pick it for consistency, report as `info`); **W3S=std** = W3Schools and the standard agree and the standard requires it; **W3S-dated** = the W3Schools advice is out of step with current practice.

## Document structure

Severity: doctype, title, charset = error; lang, viewport = error (they map to WCAG 3.1.1 / 1.4.4 risks); the rest warning.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| html/doctype | Start every HTML document with `<!doctype html>` (any case) before any element. | Required preamble; without it browsers switch to a legacy rendering mode that breaks modern CSS. W3S=std. | WHATWG https://html.spec.whatwg.org/multipage/syntax.html#the-doctype | plain HTML, framework templates that emit a full document | static: first non-comment token of an `.html` file is not a doctype | no doctype / HTML 4 doctype → `<!doctype html>` | – |
| html/html-lang | Put a `lang` attribute with a valid BCP 47 tag on the `<html>` element. | Screen readers pick pronunciation and translation tools pick the source language from it; WCAG 3.1.1 (A). Spec "encourages" it; WCAG makes the language programmatically determinable a requirement. W3S=std (W3Schools says always). | WHATWG https://html.spec.whatwg.org/multipage/semantics.html#the-html-element; WCAG 2.2 SC 3.1.1 | any | static: `<html>` without `lang` or with empty value; runtime: axe `html-has-lang`, `html-lang-valid` | `<html>` → `<html lang="en">` | – |
| html/lang-of-parts | Mark passages in another language with `lang` on the nearest element. | WCAG 3.1.2 (AA); correct voice switching. | WCAG 2.2 SC 3.1.2 | any | manual (a script cannot know the language of a passage reliably) | `<p>Merci</p>` in an English page → `<p lang="fr">Merci</p>` | – |
| html/meta-charset-utf8 | Declare `<meta charset="utf-8">` as the first child of `<head>` so it falls inside the first 1024 bytes, and save the file as UTF-8. | The spec only allows UTF-8 and requires the declaration within the first 1024 bytes; late or missing declarations cause mojibake and re-parsing. W3S=std. | WHATWG https://html.spec.whatwg.org/multipage/semantics.html#charset | any | static: no `meta[charset]`, value not utf-8, more than one, or byte offset > 1024 | `<meta charset="iso-8859-2">` → `<meta charset="utf-8">` first in head | – |
| html/single-title | Give each document exactly one non-empty `<title>` that names the page specifically. | Required by the head content model (except iframe srcdoc); WCAG 2.4.2 (A); used as tab, bookmark and search result text. | WHATWG https://html.spec.whatwg.org/multipage/semantics.html#the-title-element; WCAG 2.2 SC 2.4.2 | any (SPA: update per route) | static: zero or more than one `<title>`, or empty; manual: is it descriptive and unique | `<title>Home</title>` on every page → `<title>Pricing – Acme</title>` | – |
| html/viewport-meta | Include `<meta name="viewport" content="width=device-width, initial-scale=1">` (or at least `width=device-width`). | Without it mobile browsers lay out at a desktop width and shrink the page. MDN notes `initial-scale=1` is only needed in some overflow cases; keeping it is harmless. W3S=std practice (not a spec requirement). | MDN viewport https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport | any | static: no `meta[name=viewport]`; runtime: Lighthouse `viewport` | none → `width=device-width, initial-scale=1` | – |
| html/viewport-no-zoom-block | Never set `user-scalable=no` (or `=0`) and do not cap `maximum-scale` below 5 in the viewport meta. | Blocks pinch zoom for low-vision users; WCAG 1.4.4 needs 200% resize, MDN recommends allowing 5×. | MDN viewport (accessibility concerns); WCAG 2.2 SC 1.4.4 | any | static: regex on viewport `content`; runtime: axe `meta-viewport` | `maximum-scale=1, user-scalable=no` → remove both | – |
| html/keep-html-head-body | Write explicit `<html>`, `<head>` and `<body>` tags even though the syntax lets you omit them. | Omission is valid HTML but surprises tools and readers, and comments before `<body>` can land in the wrong place. W3S-style (W3Schools strongly discourages omitting them; spec allows it). | WHATWG optional tags https://html.spec.whatwg.org/multipage/syntax.html#optional-tags; W3Schools style guide | plain HTML | static: file has content but no `<body>` tag | `<!doctype html><title>x</title><p>…` → full skeleton | – |
| html/no-content-language-meta | Do not use `<meta http-equiv="content-language">`; use `lang` on `<html>`. | Non-conforming pragma. | WHATWG pragma directives https://html.spec.whatwg.org/multipage/semantics.html#pragma-directives | any | static: `meta[http-equiv=content-language]` | → `<html lang="…">` | – |
| html/no-x-ua-compatible | Drop `<meta http-equiv="x-ua-compatible">`. | Spec says user agents ignore it; it only ever targeted old Internet Explorer. | WHATWG https://html.spec.whatwg.org/multipage/semantics.html#pragma-directives | any | static: `meta[http-equiv=x-ua-compatible]` | `content="IE=edge"` → delete | – |

## Metadata (brief; SEO has its own file)

Severity: warning for description/canonical, info for Open Graph.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| html/meta-description-single | Use at most one `<meta name="description">` per page, with page-specific text. | The spec allows only one; it is the usual snippet source. | WHATWG https://html.spec.whatwg.org/multipage/semantics.html#meta-description | any | static: count > 1 or empty `content` | two description metas → one | – |
| html/canonical-on-link-only | Put `rel="canonical"` only on a `<link>` in `<head>`, with an absolute URL to the preferred version. | The spec allows the keyword on `link` only (not `a`/`area`/`form`) and defers to RFC 6596. | WHATWG https://html.spec.whatwg.org/multipage/links.html#link-type-canonical | any | static: `rel=canonical` on `<a>`, more than one, or relative href | `<a rel="canonical">` → `<link rel="canonical" href="https://example.com/page">` | – |
| html/open-graph-basics | If pages are shared on social sites, provide `og:title`, `og:type`, `og:image`, `og:url`, and add `og:image:alt` whenever `og:image` is set. | The four are the protocol's required set; the image alt is recommended by the protocol. Use `property=`, not `name=`. | Open Graph https://ogp.me/ (Basic Metadata, Optional Metadata) | any | static: some `og:*` present but one of the four missing; `og:image` without `og:image:alt` | `<meta name="og:title">` → `<meta property="og:title" content="…">` | – |

## Semantics and landmarks

Severity: `html/single-main`, `html/no-nested-interactive` = error; others warning; `html/no-redundant-role` = info.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| html/single-main | Have exactly one visible `<main>` per page, placed only under `html`, `body`, `div`, an unnamed `form`, or a custom element. | Spec allows at most one non-hidden `main`; it is the target of "skip to content" and the main landmark. | WHATWG https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element; ARIA in HTML | any | static: count of `<main>` without `hidden` > 1, or `main` inside `article`/`aside`/`nav`/`section`; runtime: axe `landmark-one-main` | two `<main>` → one, others `<section>` | – |
| html/landmark-elements | Mark the page regions with `header`, `nav`, `main`, `aside` and `footer` rather than `div`s with ids. | They expose banner/navigation/main/complementary/contentinfo landmarks; `header`/`footer` only become banner/contentinfo when not nested in article/aside/main/nav/section. | ARIA in HTML https://www.w3.org/TR/html-aria/ (header, footer, nav, aside rows); WCAG 2.2 SC 1.3.1 | any | static: no landmark elements at all in a full page; runtime: axe `region` | `<div id="nav">` → `<nav>` | – |
| html/section-not-generic | Use `<section>` only for a themed block that has its own heading; use `<div>` for styling or scripting wrappers. | Spec says `section` is not a generic container; it maps to `region` only when it has an accessible name. | WHATWG https://html.spec.whatwg.org/multipage/sections.html#the-section-element; ARIA in HTML | any | static: `<section>` with no heading child and no `aria-label(ledby)` (heuristic, warning) | `<section class="wrapper">` → `<div class="wrapper">` | – |
| html/nav-major-only | Wrap only major navigation blocks in `<nav>`, and label each when there is more than one. | Spec says not every link group needs `nav`; several unlabeled `nav`s are hard to tell apart. | WHATWG https://html.spec.whatwg.org/multipage/sections.html#the-nav-element | any | static: >1 `nav` without `aria-label`/`aria-labelledby` | `<nav>`×2 → `<nav aria-label="Primary">`, `<nav aria-label="Footer">` | – |
| html/article-self-contained | Use `<article>` for content that could stand alone (post, card, comment), not as a page wrapper. | Spec definition; misuse adds noise to assistive tech. | WHATWG https://html.spec.whatwg.org/multipage/sections.html#the-article-element | any | manual | `<article>` around the whole layout → `<main>` | – |
| html/address-contact-only | Use `<address>` only for contact details of the page or article author, not for any postal address. | Spec restricts it to contact information for the nearest article/body. | WHATWG https://html.spec.whatwg.org/multipage/sections.html#the-address-element | any | manual | `<address>` for a shop list → `<p>` | – |
| html/search-element | Wrap site search forms in `<search>` (or give the form `role="search"` where support is a concern). | `<search>` maps to the `search` landmark. | ARIA in HTML (search row) https://www.w3.org/TR/html-aria/ | any | static: `form` containing `input[type=search]` not inside `search`/`[role=search]` (info) | `<form>` → `<search><form>…</form></search>` | – |
| html/no-redundant-role | Do not add a `role` that repeats the element's implicit role (e.g. `role="button"` on `<button>`, `role="navigation"` on `<nav>`). | ARIA in HTML says this is not recommended; noise only. Exception: `role="list"` on a `ul` whose markers were removed. | ARIA in HTML https://www.w3.org/TR/html-aria/ | any | static: table of element→implicit role | `<nav role="navigation">` → `<nav>` | – |
| html/native-before-aria | Prefer a native element over a `div`/`span` with an ARIA role and scripted keyboard handling. | Native controls bring focus, keyboard and name/role/value for free (WCAG 2.1.1, 4.1.2). W3Schools accessibility page says the same. | ARIA in HTML; WCAG 2.2 SC 4.1.2; W3Schools html_accessibility | any | static: `[role=button]`, `[role=link]`, `[role=checkbox]` on non-interactive elements | `<div role="button">` → `<button type="button">` | – |
| html/text-semantics | Use `strong`/`em` for importance/stress and `b`/`i` only for offset text without extra importance; never pick them for looks. | Spec gives each a distinct meaning; visual bold/italic belongs in CSS. | WHATWG https://html.spec.whatwg.org/multipage/text-level-semantics.html | any | manual | `<b>Warning:</b>` meaning importance → `<strong>` | – |
| html/abbr-title-expansion | When `title` is set on `<abbr>`, make it the expansion and nothing else. | Spec requirement. | WHATWG https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-abbr-element | any | manual | `title="click for info"` → `title="World Health Organization"` | – |
| html/time-datetime | Give `<time>` a machine-readable `datetime` whenever its text is not itself a valid date/time string. | Spec requirement; lets tools parse dates. | WHATWG https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-time-element | any | static: `<time>` with child elements and no `datetime` | `<time>next Tuesday</time>` → `<time datetime="2026-11-17">next Tuesday</time>` | – |
| html/blockquote-attribution-outside | Keep the attribution of a quote outside `<blockquote>` (e.g. in a `figcaption`), and make `cite` a valid URL. | Spec: the blockquote holds only the quoted content. | WHATWG https://html.spec.whatwg.org/multipage/grouping-content.html#the-blockquote-element | any | manual | `<blockquote>… — Author</blockquote>` → `<figure><blockquote>…</blockquote><figcaption>Author</figcaption></figure>` | – |

## Headings

Severity: `html/heading-no-skip` = error (spec "must" since the outline rewrite); others warning.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| html/heading-no-skip | Each heading may go at most one level deeper than the previous heading (h2 → h3 is fine, h2 → h4 is not). | The current spec makes this a "must"; screen-reader users navigate by level. W3Schools accessibility page says the same. | WHATWG https://html.spec.whatwg.org/multipage/sections.html#headings-and-outlines-2; WCAG 2.2 SC 1.3.1 | any (per rendered page, components need the page context) | static per file is noisy for components; runtime: axe `heading-order` | `<h1>`→`<h3>` → `<h1>`→`<h2>` | – |
| html/has-h1 | Give each page at least one `<h1>` that states its topic. | Spec says the outline should have a level-1 heading ("should"). | WHATWG https://html.spec.whatwg.org/multipage/sections.html#headings-and-outlines-2 | any | runtime: axe `page-has-heading-one` | page starts at `<h2>` → add `<h1>` | – |
| html/no-nested-h1-outline | Do not rely on nesting `<h1>` inside `<section>`/`<article>` to create sub-levels; the level is the number in the tag (adjusted only by the new `headingoffset`). | The old sectioning outline algorithm is gone; browsers never exposed it. | WHATWG , `headingoffset` https://html.spec.whatwg.org/multipage/sections.html#attr-headingoffset | any | static: more than one `<h1>` inside nested sectioning (warning) | `<section><h1>` for a sub-topic → `<h2>` | – |
| html/heading-not-for-style | Use heading elements for structure only, and size text with CSS. | Fake headings distort the outline; W3Schools accessibility page says the same. | W3Schools html_accessibility; WCAG 2.2 SC 1.3.1, 2.4.6 | any | manual | `<h4>` for small bold text → `<p class="eyebrow">` | – |
| html/hgroup-subtitle | Put a subtitle/tagline next to its heading in `<hgroup>` with `<p>`, not as another heading level. | Spec content model: one heading plus `p` elements. | WHATWG https://html.spec.whatwg.org/multipage/sections.html#the-hgroup-element | any | static: `hgroup` with more than one `h1`–`h6` | `<h1>…</h1><h2>tagline</h2>` → `<hgroup><h1>…</h1><p>tagline</p></hgroup>` | – |

## Links vs buttons

Severity: error for `html/no-nested-interactive`, `html/link-has-href`, `html/button-type`; warning otherwise.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| html/link-navigates-button-acts | Use `<a href>` to go to a URL and `<button>` to do something on the current page. | Keyboard, context menu, new tab and assistive-tech behaviour differ; MDN advises links only for real URLs. | MDN `<a>` (accessibility) https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a | any | static: `a[href="#"]`, `a[href^="javascript:"]`, `a` with click handler and no href | `<a href="#" onclick="open()">` → `<button type="button">` | – |
| html/link-has-href | Do not use `<a>` without `href` as a clickable control. | Without `href` it is only a placeholder: not focusable, Enter does nothing, role is generic. | WHATWG https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element; MDN `<a>` | any | static: `<a>` without `href` but with click handler / `tabindex` | `<a onclick>` → `<button type="button">` | – |
| html/no-div-click | Do not attach click handlers to `div`/`span`/`li` as the only way to trigger an action. | Not reachable by keyboard (WCAG 2.1.1) and has no role (4.1.2). | WCAG 2.2 SC 2.1.1, 4.1.2 | any (JSX `onClick`, Vue `@click`, etc.) | static: click handler on non-interactive element without role+tabindex+key handler | `<div onclick>` → `<button type="button">` | – |
| html/no-nested-interactive | Never put a link, button, input or element with `tabindex` inside an `<a>` or `<button>`. | Spec forbids interactive content descendants; behaviour is undefined across browsers. | WHATWG https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element (a content model); (button) | any | static: DOM nesting check; Nu checker reports it | `<a><button>Buy</button></a>` → style the `<a>` | – |
| html/button-type | Give every `<button>` an explicit `type` (`button`, `submit` or `reset`). | A typeless button in a form submits it (the spec's "Auto" state resolves to submit unless `command`/`commandfor` is set or it sits in a `select`), which reloads the page by surprise. | WHATWG https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element; MDN `<button>` | any | static: `<button>` without `type` | `<button>Close</button>` → `<button type="button">Close</button>` | – |
| html/link-text-meaningful | Make link text say where it goes; avoid bare "click here", "read more", "here". | WCAG 2.4.4 (A); W3Schools accessibility page and MDN agree. | WCAG 2.2 SC 2.4.4; MDN `<a>`; W3Schools html_accessibility | any | static: link text in a deny-list (language-dependent, warning); runtime: Lighthouse `link-text` | `<a>here</a>` → `<a>pricing plans</a>` | – |
| html/control-accessible-name | Every link and button needs an accessible name: visible text, an `alt` on its only image, or `aria-label`. | Icon-only controls are announced as "button" with nothing else; WCAG 4.1.2. | MDN `<button>` (icon buttons); WHATWG https://html.spec.whatwg.org/multipage/images.html#a-link-or-button-containing-nothing-but-the-image (link/button containing only an image) | any | static: `a`/`button` with no text, no `aria-label(ledby)`, no `img[alt]` child; runtime: axe `button-name`, `link-name` | `<button><svg/></button>` → `<button aria-label="Close"><svg aria-hidden="true"/></button>` | – |
| html/target-blank-rel | Know that `target="_blank"` now implies `noopener`; add `rel="noreferrer"` only if you also want to hide the referrer, and tell users a new tab will open. | The spec's noopener algorithm returns true for `_blank` unless `rel=opener`; MDN still suggests explicit `noopener` for old browsers. | WHATWG https://html.spec.whatwg.org/multipage/links.html#following-hyperlinks; MDN `<a>` | any | static: `target=_blank` without any notice in text (manual for the notice) | `rel="noopener"` missing is now low risk → info only | – |
| html/skip-link | Provide a "skip to main content" link as the first focusable item, pointing to `<main>`'s id. | Helps keyboard users bypass repeated blocks (WCAG 2.4.1). | MDN `<a>` (skip links); WCAG 2.2 SC 2.4.1 | sites with repeated navigation | static: first focusable `a` in body does not target `main` (info); manual | none → `<a class="skip-link" href="#content">` | – |

### Where W3Schools differs from the standard or modern practice (be honest in the skill)

- Things W3Schools calls recommended that the standard actually requires: doctype, a single `<title>`, UTF-8 declaration within 1024 bytes, `alt` on images (with narrow exceptions). Report these as errors.
- Things W3Schools recommends that the standard does not require (lowercase names, closing optional end tags, quoting, no spaces around `=`, two-space indent, lowercase file names): style only; report as `info` and defer to the project's formatter.
- Dated or weaker advice: the accessibility page frames `alt` as "describe what the image shows", while the spec asks for replacement text and empty `alt` for decorative images; it does not cover ARIA, focus or decorative images. W3Schools says nothing about heading skips being a conformance error (the WHATWG spec made that a "must" with the new outline/`headingoffset` text). The "no tabs" rule conflicts with teams that prefer tabs for adjustable indentation width.
- The style guide still discusses `.htm` and the trailing slash for XHTML; both are legacy concerns.

## Notes for skill authors

- Short skill (always loaded): doctype, lang, charset, viewport (no zoom block), one title, one main + landmarks, heading order, `button type` + links vs buttons + accessible names, labels + autocomplete tokens, `alt` rules (incl. decorative `alt=""`), `width`/`height` on images, `iframe title`, captions track, no obsolete elements. Reference file: full obsolete list, autofill token list, W3Schools style table, table header details, picture/srcset details.
- Noisy rules: `html/heading-no-skip` per component file (components do not know their page level — check rendered pages), `html/link-text-meaningful` (language-dependent deny list), `html/input-type-fits` and `html/no-number-for-codes` (name heuristics), `html/section-not-generic`, all `html/style-*` rules (formatters own them; turn off when Prettier is present).
- Controversial: trailing slash on void elements (Prettier adds it by default; spec says it does nothing); `rel="noopener"` (now implied by the spec and current browsers — do not raise as error); `initial-scale=1` (MDN now says optional).
- Changes often, recheck before release: WHATWG heading-level "must" and `headingoffset`/`headingreset` (new); button "Auto" type state with `command`/`commandfor`; ARIA in HTML (new Recommendation 11 Aug 2026); `vnu-jar` version (date-based, e.g. 26.11.9); axe/Lighthouse rule ids.
- Automated checks (axe, Lighthouse, Nu) find only part of the problems; alt text quality, link text meaning, heading wording, caption accuracy and language of parts need a person. Say "helps you work to WCAG 2.2 AA", never more.
