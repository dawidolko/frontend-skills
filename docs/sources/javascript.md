## Language best practices and common mistakes

Severity: error for `js/strict-equality`, `js/no-eval`, `js/no-implicit-globals`, `js/no-var`; warning for the rest.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| js/strict-equality | Compare with `===`/`!==`, not `==`/`!=`. | Loose equality converts types (`10 == "10"`). W3S=modern. | W3Schools js_best_practices, js_mistakes | JS/TS | static: ESLint `eqeqeq` | `if (x == "1")` → `if (x === 1)` | – |
| js/no-var | Declare with `const` by default and `let` when you reassign; never `var`. | Block scope, no redeclaration, TDZ catches use-before-define. W3Schools explains `var` and only marks redeclaring as "not recommended" (W3S-dated). | W3Schools js_best_practices; ESLint `no-var`, `prefer-const` | JS/TS | static: ESLint `no-var`, `prefer-const` | `var i` → `let i` | – |
| js/const-is-not-frozen | Remember that `const` blocks reassignment, not mutation of objects/arrays. | W3Schools presents `const` objects as protected from change, which is only about reassignment (W3S-dated nuance). Use `Object.freeze` or `readonly` types when immutability matters. | W3Schools js_best_practices | JS/TS | manual | – | – |
| js/declare-near-use | Declare variables where they are first needed, initialised, not hoisted to the top of the function. | W3Schools says "declarations on top", a `var`-era habit (W3S-dated); with block-scoped `let`/`const` the narrowest scope is clearer. Initialising at declaration (W3Schools) is still good. | W3Schools js_best_practices | JS/TS | manual | – | – |
| js/no-implicit-globals | Never assign to undeclared names and keep top-level script state out of the global object (use modules). | Undeclared assignment creates a global or throws in strict mode; other scripts can overwrite globals. W3S=modern. | W3Schools js_best_practices, js_strict; MDN Modules (module scope) | plain JS | static: ESLint `no-undef`, `no-implicit-globals`, `no-global-assign` | `count = 0` (undeclared) → `let count = 0` in a module | – |
| js/use-modules-or-strict | Write code as ES modules (strict automatically) or, for classic scripts, start with `"use strict"`. | Strict mode turns silent mistakes into errors (undeclared vars, `with`, duplicate params). MDN: modules are always strict. W3Schools covers `"use strict"` but not that modules are strict (W3S-dated). | MDN Modules https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules#whats_a_module; W3Schools js_strict | plain JS | static: classic script file without `"use strict"` and without import/export | – | – |
| js/no-eval | Do not use `eval`, `new Function`, or string arguments to `setTimeout`/`setInterval`. | Runs arbitrary text as code (XSS); blocks CSP without `unsafe-eval`. W3S=modern. | W3Schools js_best_practices; ESLint `no-eval`, `no-implied-eval`, `no-new-func` | JS/TS | static: those ESLint rules | `setTimeout("go()", 10)` → `setTimeout(go, 10)` | – |
| js/no-wrapper-constructors | Use literals (`""`, `0`, `[]`, `{}`, `/re/`) instead of `new String/Number/Boolean/Object/Array`. | Wrapper objects compare and type-check unexpectedly (`new String("a") !== "a"`). W3S=modern. | W3Schools js_best_practices; ESLint `no-new-wrappers` | JS/TS | static: ESLint `no-new-wrappers`, `no-array-constructor` | `new Array()` → `[]` | – |
| js/no-with | Never use `with`. | Forbidden in strict mode and modules; W3S=modern (though the reason is now syntax, not speed). | W3Schools js_performance, js_strict; ESLint `no-with` | plain JS | static: ESLint `no-with` | – | – |
| js/default-params | Use default parameter syntax instead of checking `=== undefined` inside the function. | W3Schools shows both; the ES2015 form is the modern one. | W3Schools js_best_practices | JS/TS | manual / static pattern `if (x === undefined) x =` at function start | `if (y === undefined) y = 0` → `function f(x, y = 0)` | – |
| js/switch-default | End `switch` statements with a `default` branch (or, in TS over a union, an exhaustive `never` check). | W3S=modern for JS; in TS an exhaustiveness check catches new union members better than a silent default. | W3Schools js_best_practices; ESLint `default-case` | JS/TS | static: ESLint `default-case` (turn off where typescript-eslint `switch-exhaustiveness-check` is used — rule name not re-read today) | – | – |
| js/no-cond-assign | Do not assign inside an `if`/`while` condition by accident. | `if (x = 10)` assigns and is always truthy. | W3Schools js_mistakes; ESLint `no-cond-assign` | JS/TS | static: ESLint `no-cond-assign` | `if (x = 10)` → `if (x === 10)` | – |
| js/no-return-linebreak | Never put a line break right after `return` before its value. | Automatic semicolon insertion makes the function return `undefined`. | W3Schools js_mistakes; ESLint `no-unreachable` catches the dead line | JS/TS | static: ESLint `no-unreachable` / formatter | `return\n {…}` → `return {…}` | – |
| js/no-empty-statement-if | Do not put a semicolon right after an `if (…)` condition. | The block then runs unconditionally. | W3Schools js_mistakes | JS/TS | static: ESLint `no-empty` / formatter (rule mapping not re-read) | `if (a);{…}` → `if (a) {…}` | – |
| js/number-vs-string-plus | Convert to numbers explicitly before adding values that may be strings (form inputs, URL params). | `+` concatenates if either side is a string (`"5" + 2 === "52"`). | W3Schools js_best_practices, js_mistakes | JS/TS | manual (TS catches most) | `input.value + 1` → `Number(input.value) + 1` or `input.valueAsNumber` | – |
| js/float-money | Do not compute money with binary floats; work in integer minor units (cents) or a decimal library. | `0.1 + 0.2 !== 0.3`; W3Schools shows the scale-up trick. | W3Schools js_mistakes | JS/TS | manual | `price * 1.23` on floats → integer cents | – |
| js/no-array-named-keys | Do not put named keys on arrays; use an object or `Map`. | Named keys are object props, not elements: `length` and iteration ignore them. | W3Schools js_mistakes | JS/TS | manual / TS | `arr["name"] = …` → `map.set("name", …)` | – |
| js/null-undefined-check | Test `typeof x === "undefined"` (or `x == null` deliberately, or `?.`/`??`) rather than reading undeclared names. | Reading an undeclared variable throws; `?.` and `??` are the modern tools for absent values. | W3Schools js_mistakes | JS/TS | manual | `if (obj !== null && obj.x)` → `obj?.x` | – |
| js/json-no-trailing-commas | Do not put trailing commas or comments in JSON files or `JSON.parse` input. | Valid in JS literals, invalid in JSON. | W3Schools js_mistakes | JSON | static: JSON parse of `*.json` (except `tsconfig.json`, which allows comments) | – | – |

## Async code and error handling

Severity: error for `js/no-floating-promises`, `js/fetch-check-ok`; warning otherwise.

| id | rule (own words, one sentence) | why | source (name, URL, section/criterion) | applies to | check | bad → good | light library |
|---|---|---|---|---|---|---|---|
| js/no-floating-promises | Every promise must be awaited, returned, `.catch`-ed, or explicitly marked `void`. | Otherwise rejections vanish or surface as unhandled rejections. | typescript-eslint `no-floating-promises` (needs type info; in `recommended-type-checked`) https://typescript-eslint.io/rules/no-floating-promises/ | TS (JS via type-aware lint) | static: that rule | `save();` → `await save();` | – |
| js/no-misused-promises | Do not pass async functions where a sync callback or boolean is expected (e.g. `if (promise)`, `forEach(async …)`). | The promise is ignored or always truthy. | typescript-eslint `no-misused-promises` (related to the rule above) | TS | static | `arr.forEach(async x => …)` → `for (const x of arr) await …` or `Promise.all` | – |
| js/fetch-check-ok | After `fetch`, check `response.ok` (or `status`) before reading the body. | `fetch` resolves on 404/500 and rejects only on network failure or abort. | MDN fetch https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch | JS/TS | static: `await fetch(...)` followed by `.json()` with no `ok`/`status` reference (heuristic) | `(await fetch(u)).json()` → check `res.ok` then `res.json()` | – |
| js/fetch-timeout-abort | Give network calls a cancel path: an `AbortController` signal for user/route cancel and `AbortSignal.timeout(ms)`, combined with `AbortSignal.any` when both are needed. | Prevents hung requests and races after navigation. `timeout` is Baseline since April 2024 and `any` since March 2024 (MDN); timeout rejects with `TimeoutError`, abort with `AbortError`. | MDN AbortSignal.timeout https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/timeout_static; AbortSignal.any https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/any_static | JS/TS | static: `fetch(` without `signal` in client code (info) | `fetch(u)` → `fetch(u, { signal: AbortSignal.timeout(8000) })` | – |
| js/throw-error-objects | Throw and reject only with `Error` instances (or subclasses). | Keeps stack traces and `instanceof` checks. | ESLint `no-throw-literal`, `prefer-promise-reject-errors` https://eslint.org/docs/latest/rules/ | JS/TS | static: those rules | `throw "fail"` → `throw new Error("fail")` | – |
| js/error-cause | When you catch and rethrow with more context, pass the original as `{ cause }`. | Keeps the root error; Baseline since September 2021 (MDN). | MDN Error cause https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/cause | JS/TS | static: `throw new Error(` inside `catch (e)` without `cause` (info) | `throw new Error("Load failed")` → `throw new Error("Load failed", { cause: e })` | – |
| js/no-swallowed-errors | Do not leave `catch` blocks empty or only `console.log` them in production paths; show the user a recoverable state and report the error. | Silent failures hide bugs. | ESLint `no-empty` (core; not re-read today) | JS/TS | static: empty catch | `catch {}` → `catch (e) { report(e); showError(); }` | – |
| js/unhandledrejection-reporter | Register one `unhandledrejection` (and `error`) listener on `window` to report what slipped through, not as the main error handling. | Fires for rejected promises with no handler; cross-origin script rejections are not reported. | MDN unhandledrejection https://developer.mozilla.org/en-US/docs/Web/API/Window/unhandledrejection_event | apps | static: app entry without such listener (info) | – | – |
| js/no-async-executor | Do not pass an `async` function to `new Promise(...)`. | Errors thrown inside are lost and the wrapper is usually unnecessary. | ESLint `no-async-promise-executor` | JS/TS | static | `new Promise(async (res) => …)` → plain async function | – |
| js/parallel-await | Run independent async work with `Promise.all`/`allSettled` instead of `await` in a loop. | Sequential awaits add latency. | ESLint `no-await-in-loop` (Possible Problems) | JS/TS | static: that rule (noisy when order matters) | `for (u of us) await get(u)` → `await Promise.all(us.map(get))` | – |

## TypeScript at the boundaries

Current version: `typescript@7.0.2` (npm `latest`, published 2026-07-08, Apache-2.0). TS 7 is the native (Go) compiler; it ships no programmatic API yet, so tools that import `typescript` (typescript-eslint, Vue/Svelte/Astro/Angular/MDX editor tooling) need the `@typescript/typescript6` compatibility package (6.0.2, Apache-2.0, npm) per the 7.0 announcement. Severity: error for `ts/strict`, `ts/no-explicit-any`, `ts/validate-untrusted`; warning otherwise.

## Notes for skill authors

- Short skill: strict equality, `const`/`let`, modules + `defer`, no eval, handle every promise, `fetch` checks `ok` + timeouts, throw `Error` with `cause`, `textContent` over `innerHTML`, delegation + `signal` cleanup + passive listeners, read-then-write DOM, feature detection; TS: `strict` on, `unknown` not `any`, validate at boundaries. Reference file: W3Schools style table, tsconfig flag list, deprecated-option list, validator comparison.
- Most rules map to existing ESLint/typescript-eslint rules — the skill should tell the agent to run the project's linter rather than re-implement checks; type-aware rules (`no-floating-promises`, `no-misused-promises`, `no-unsafe-*`) need a typed lint setup, which under TS 7 needs the `@typescript/typescript6` alias.
- Noisy: `js/fetch-check-ok`, `js/no-layout-thrashing`, `ts/no-cast-to-silence`, `js/parallel-await` (order sometimes matters), all `js/style-*` (formatter owns them; turn off when Prettier/Biome config exists).
- W3Schools conflicts to state plainly: `var`-era "declare at top", bottom-of-body scripts and `onload` injection, "no trailing comma" vs formatter defaults, `arr.length` caching, "DOM access is very slow". Keep W3Schools' good parts (===, no eval, no globals, literals, default params, switch default).
- Changes often, recheck before release: TypeScript (7.x has no API yet; 7.1 expected to add one; `beta` tag already 7.1.0-beta), tsconfig defaults, `setHTML`/Sanitizer support status, validator versions/sizes, ESLint major (10.x now).
- Automated checks cannot judge whether a sanitizer config is safe, whether an error message helps users, or whether a validation schema matches the real API — those need a person.
