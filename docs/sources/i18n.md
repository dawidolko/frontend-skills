# Internationalisation: sources and candidate rules

Read on 2026-11-11. Primary sources:

- W3C Internationalization Activity: https://www.w3.org/International/
  - Declaring language in HTML: https://www.w3.org/International/questions/qa-html-language-declarations
  - Structural markup and right-to-left text (`dir`, `bdi`, `dirname`): https://www.w3.org/International/questions/qa-html-dir
  - Text size in translation: https://www.w3.org/International/articles/article-text-size
- MDN `lang` global attribute: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/lang
- MDN `Intl.Collator`: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Collator
- Baseline data: `web-features` npm package v3.45.0, `data.json` (https://www.npmjs.com/package/web-features), same data as https://webstatus.dev
- Unicode CLDR plural rules chart: https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html (latest CLDR release 49, 2026-10-22, per https://cldr.unicode.org/index/downloads)
- ICU user guide, Formatting Messages: https://unicode-org.github.io/icu/userguide/format_parse/messages/
- Unicode MessageFormat 2: https://messageformat.unicode.org/ ; CLDR 47 release note (MF2 "Stable", 2025-03-13): https://cldr.unicode.org/downloads/cldr-47
- TC39 Intl.MessageFormat proposal (Stage 1): https://github.com/tc39/proposal-intl-messageformat
- Google localized versions (hreflang): https://developers.google.com/search/docs/specialty/international/localized-versions
- WCAG 2.2 SC 3.1.1 Language of Page, 3.1.2 Language of Parts: https://www.w3.org/TR/WCAG22/#language-of-page
- npm registry (`registry.npmjs.org/<pkg>/latest`) for version, licence, dependencies; bundlephobia API (`bundlephobia.com/api/size`) for min and min+gzip.

## Language and direction in markup

Severity in column `sev`.

| id | rule (own words, one sentence) | why | source | applies to | check | bad → good | light library | sev |
|---|---|---|---|---|---|---|---|---|
| i18n/html-lang | The `<html>` element carries a valid BCP 47 `lang` matching the page's main language (per locale in multi-locale apps). | Screen readers pick pronunciation from it (WCAG 3.1.1); `:lang()` and browser features rely on it; `body` does not cover `head`. | W3C language declarations; MDN `lang`; WCAG 2.2 SC 3.1.1 | any | static: `<html>` without `lang`, empty `lang`, or hard-coded `lang="en"` in a multi-locale layout; runtime: axe `html-has-lang`, `html-lang-valid` | `<html>` → `<html lang="pl">`; Next/Nuxt layouts: set from active locale | – | error |
| i18n/lang-of-parts | Mark inline passages in another language with `lang` on the nearest element (or a `span`/`bdi`). | WCAG 3.1.2; correct pronunciation and font selection. | W3C language declarations; WCAG 2.2 SC 3.1.2 | any | manual (static: language-switcher entries without `lang`) | `<a>Français</a>` → `<a lang="fr" hreflang="fr">Français</a>` | – | warning |
| i18n/no-meta-content-language | Do not declare page language with `<meta http-equiv="Content-Language">`. | W3C says never use it for that; `lang` is what counts. | W3C language declarations | any | static: that meta present | meta → `lang` on `<html>` | – | info |
| i18n/dir-on-html | For right-to-left locales set `dir="rtl"` on `<html>` together with `lang`; set direction in markup, not with CSS `direction`. | Base direction belongs to content; CSS can be lost (e.g. reader modes, syndication). | W3C qa-html-dir | any with RTL locales | static: RTL locale list (ar, he, fa, ur…) without `dir` binding; CSS `direction: rtl` on html/body | `html { direction: rtl }` → `<html lang="ar" dir="rtl">` | – | error |
| i18n/dir-auto-user-text | Use `dir="auto"` on elements and fields holding user-generated or runtime text of unknown direction. | Browser picks direction from first strong character (not perfect). | W3C qa-html-dir | any | manual / static (inputs/textarea for comments, chat) | `<textarea>` → `<textarea dir="auto" dirname="comment.dir">` | – | info |
| i18n/bdi-for-unknown | Wrap inserted names or values of unknown direction in `<bdi>` (or an element with `dir="auto"`). | Prevents neighbouring punctuation and numbers from being reordered. | W3C qa-html-dir; MDN `lang` example | any | manual / static (interpolated user names inside sentences) | `{user} wrote 3 posts` → `<bdi>{user}</bdi> …` | – | info |
| i18n/hreflang-on-switcher | Language-switcher links carry `hreflang` and `lang` of the target, plus head `hreflang` alternates (see seo.md). | Search and assistive tech. | Google localized versions | any | static | – | – | info |

|---|---|---|---|---|---|---|---|---|

## Strings and messages

| id | rule | why | source | applies to | check | bad → good | light library | sev |
|---|---|---|---|---|---|---|---|---|
| i18n/no-string-concat | Never build a user-facing sentence by joining translated fragments or fragments with values; use one message with named placeholders. | Word order differs by language; translators cannot reorder fragments. | ICU Formatting Messages | JS/TS, all frameworks | static: `t('a') + x + t('b')`, template literal mixing `t()` calls, JSX text split around `{t()}` | `t('hello') + name` → `t('hello', { name })` with "Hello, {name}" | i18next, vue-i18n, next-intl, Paraglide, FormatJS (below) | error |
| i18n/icu-plural | Pluralise with the locale's plural rules (ICU `{count, plural, …}` or `Intl.PluralRules`), always with an `other` branch; never `count === 1 ? a : b`. | Many languages have more than two forms. | ICU Formatting Messages; CLDR plural rules | any | static: ternary on `=== 1`/`> 1` choosing strings; plural message missing `other` | `n===1?'file':'files'` → `{n, plural, one {# file} other {# files}}` | – | error |
| i18n/polish-plural-forms | Polish (and similar) translations must provide `one`, `few`, `many` and `other`. | CLDR `pl` cardinal: one (1), few (2–4, 22–24…, not 12–14), many (0, 5–21, 25…, 100…), other (decimals e.g. 1,5); ordinal: other only. English has only one/other; Arabic has zero/one/two/few/many/other. | CLDR plural rules chart (CLDR 49) | translation files | static: for each plural message in `pl` check categories from `Intl.PluralRules('pl').resolvedOptions().pluralCategories` | `pl: {one, other}` → `{one, few, many, other}` | – | error |
| i18n/select-outside-plural | Put `select` (e.g. gender) outside and `plural` inside, with complete sentences in each branch. | Keeps branches translatable as whole sentences. | ICU Formatting Messages | messages | static (parse ICU) | – | – | info |
| i18n/same-keys-all-locales | Every locale file has the same key set as the source locale (no missing, no orphaned keys), and placeholders match. | Missing keys show raw keys or fallback text; mismatched placeholders break at runtime. | ICU Formatting Messages (placeholders); library docs | JSON/YAML/PO message files | static: diff key sets and `{placeholder}` names | `pl.json` missing `cart.empty` → add | – | error |
| i18n/no-hardcoded-ui-text | User-visible strings in components go through the i18n layer once a project has more than one locale. | Untranslatable otherwise. | W3C Internationalization (general guidance) | frameworks | static: JSX text / template text nodes and `aria-label`, `alt`, `title`, `placeholder` literals (noisy) | `<button>Save</button>` → `<button>{t('save')}</button>` | – | warning |
| i18n/mf2-status | Treat MessageFormat 2 as stable syntax in Unicode (CLDR 47, 2025-03-13) but `Intl.MessageFormat` in JS is only a TC39 Stage 1 proposal; do not assume a native API. | Avoid recommending an API browsers do not have. | CLDR 47 note; TC39 proposal | JS | – | – | `messageformat@4` noted by CLDR as tech-preview JS implementation (not checked further) | info |

## Formatting and sorting with Intl

| id | rule | why | source | applies to | check | bad → good | light library | sev |
|---|---|---|---|---|---|---|---|---|
| i18n/intl-datetime | Format dates and times with `Intl.DateTimeFormat` (or `toLocaleDateString` with an explicit locale), never by string-building. | Order, separators, month names, 12/24-hour clock and calendars differ. | ECMA-402 via MDN; Baseline `intl` widely | JS | static: `getDate()+'/'+getMonth()`, `moment().format('MM/DD')` with fixed pattern in UI | `` `${d}/${m}` `` → `new Intl.DateTimeFormat(locale,{dateStyle:'medium'}).format(date)` | none needed (built in) | warning |
| i18n/intl-number | Format numbers, currency, percent and units with `Intl.NumberFormat`. | Decimal/grouping separators and currency placement vary (Node 23.7 / ICU 76.1 gives `1234,50 zł` for pl, no grouping below 5 digits, and `12 345,50 zł` with a non-breaking space for larger values). | MDN Intl; Baseline widely | JS | static: `toFixed(2)` concatenated with currency symbol in UI | `'$'+n.toFixed(2)` → `new Intl.NumberFormat(locale,{style:'currency',currency}).format(n)` | – | warning |
| i18n/intl-relative-time | Use `Intl.RelativeTimeFormat` for "in 3 days" / "2 hours ago". | Plural and word order handled per locale. | Baseline widely | JS | static: manual "ago" strings | – | – | info |
| i18n/intl-list | Use `Intl.ListFormat` for "A, B and C". | Conjunctions and comma rules vary. | Baseline widely | JS | static: `.join(', ')` + `' and '` | – | – | info |
| i18n/intl-segmenter | Use `Intl.Segmenter` to count or truncate user-perceived characters/words, not `.length` or `split(' ')`. | Emoji and combining marks are several code units; some languages have no spaces. | Baseline widely (2026-10-16) | JS | static: truncation by `.slice(0, n)` on display text | `s.slice(0,20)` → graphemes from `Intl.Segmenter` | – | info |
| i18n/intl-collator | Sort user-visible strings with `Intl.Collator(locale).compare` (reuse one instance; `numeric:true` for natural order), not default `sort()` or `<`. | Code-unit order is wrong for accents and per-language letters (e.g. ä after z in Swedish). | MDN Intl.Collator; Baseline widely | JS | static: `.sort()` without comparator on string arrays shown in UI; `a.name > b.name` | `names.sort()` → `names.sort(new Intl.Collator(locale).compare)` | – | warning |
| i18n/explicit-locale | Pass the active app locale to Intl constructors instead of relying on the runtime default. | SSR server locale differs from the user; hydration mismatches. | MDN Intl (locales argument) | SSR frameworks | static: `new Intl.*()` / `toLocale*String()` without a locale argument in SSR code | `toLocaleDateString()` → `toLocaleDateString(locale)` | – | warning |
| i18n/time-zone-explicit | When rendering on the server, set `timeZone` explicitly or render on the client. | Server and client zones differ, causing wrong times and hydration mismatch. | MDN `Intl.DateTimeFormat` `timeZone` option | SSR | manual / static | – | – | info |

## Notes for skill authors

- Short skill: `lang`/`dir` on `<html>`, no concatenation, plural via ICU/`Intl.PluralRules`, same keys in every locale,
  Intl for dates/numbers/sorting, logical properties when an RTL locale exists. Reference file: Baseline table, CLDR
  categories per target language, expansion table, library table.
- Generate the expected plural categories per locale at check time with `new Intl.PluralRules(locale).resolvedOptions().pluralCategories`
  (Node's ICU), and say which Node/ICU version was used, rather than hard-coding them.
- Noisy: "hard-coded UI text" and "physical CSS property" rules in single-locale, LTR-only projects; gate them on the
  project actually having more than one locale or an RTL locale. `.sort()` heuristics fire on non-UI data.
- Controversial: pseudo-locale expansion percentages; W3C's table is an average, not a target.
- Changes often: CLDR data (new release roughly twice a year; plural rules rarely change but do), Intl Baseline
  (`DurationFormat`, `Locale` info are only newly available), library versions, MF2/Intl.MessageFormat status.
- Only a person can check: translation quality, cultural fit, whether mirrored icons make sense, whether layouts hold
  with real translations. Automated checks find only part of the problems.
