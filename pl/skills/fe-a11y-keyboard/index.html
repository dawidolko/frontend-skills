Dostępność

Keyboard access and focus

Makes every control work from the keyboard in any stack (HTML, React, Vue, Svelte, Angular, Astro) to WCAG 2.2 AA as a target - native controls, focus order, visible focus, focus not hidden by sticky bars, skip links, focus after route changes, no traps. Use when building interactive UI, custom widgets or a layout, removing an outline, or when asked "can I use this with a keyboard".

fe-a11y-keyboardkażdego projektu webowego9 regułładowane zawsze: 93 tokeny; przy użyciu: 1127 tokenów; w referencjach na żądanie: 1593 tokeny.

Jak go używać

Po instalacji agent sam ładuje skill, gdy zadanie pasuje do jego opisu. Możesz też poprosić o niego własnymi słowami, na przykład:

Frazy z opisu skilla, po których agent go wybiera (po angielsku, jak w skillu):

  • can I use this with a keyboard

A żeby sprawdzić i poprawić pracę:

  • Użyj skilla fe-a11y-keyboard na tym pliku.
  • Uruchom audyt front-endu na moich zmianach i popraw wszystko, co poważne.
  • Wyjaśnij a11y/no-click-on-static i popraw to tutaj.

Reguły, których uczy

  • a11y/no-click-on-static

    A click handler belongs on a button or link; a static element with one also needs a role, tabindex and a key handler.

    poważnastatyczneWCAG 2.1.1, 4.1.2

  • a11y/link-is-link

    An <a> is a real link with an href; an action is a <button>, never <a> without href, href="#" or javascript:.

    poważnastatyczneWCAG 2.1.1, 4.1.2

  • a11y/positive-tabindex

    No element has a tabindex greater than 0; focus order follows the source order.

    poważnastatyczneWCAG 2.4.3

  • a11y/focus-visible

    Never remove the focus outline without drawing a visible replacement for keyboard focus.

    poważnastatyczneWCAG 2.4.7

  • a11y/focus-not-obscured

    Sticky headers, footers, cookie banners and chat widgets never fully cover the element that has keyboard focus.

    poważnaręczneWCAG 2.4.11

  • a11y/skip-link

    Pages with repeated header or navigation start with a "Skip to main content" link whose target exists and takes focus.

    umiarkowanaw przeglądarceWCAG 2.4.1

  • a11y/no-keyboard-trap

    Keyboard focus can always leave a component with Tab, Shift+Tab or Escape; only an open modal keeps focus inside.

    krytycznaręczneWCAG 2.1.2

  • a11y/focus-route-change

    After a client-side route change, focus moves to the new page's heading or main region and the new title is announced.

    umiarkowanaręczneWCAG 2.4.3, 4.1.3

  • a11y/scrollable-region-focusable

    A scrolling region with no focusable content inside can itself take focus (tabindex="0") and has a name.

    poważnaw przeglądarceWCAG 2.1.1

Skrót reguł

Ta część jest kopiowana do zawężonego pliku reguł każdego agenta, więc musi być zrozumiała sama w sobie:

  • Actions are <button type="button">, navigation is <a href>; never a click handler on a div or span (a11y/no-click-on-static).
  • Never <a> without href, with href="#" or javascript: as a button (a11y/link-is-link).
  • Never tabindex above 0; fix the order in the DOM, and keep CSS order and *-reverse from scrambling it (a11y/positive-tabindex).
  • Never remove the outline without a visible :focus-visible style of at least 3:1 contrast (a11y/focus-visible).
  • Sticky headers, footers and banners never cover the focused element: set scroll-padding (a11y/focus-not-obscured).
  • Layouts with repeated navigation start with a working "Skip to main content" link (a11y/skip-link).
  • Focus can always leave a component with Tab or Escape; only an open modal traps it (a11y/no-keyboard-trap).
  • After a client-side route change, move focus to the new heading or <main> (a11y/focus-route-change).
  • Scrollable regions with nothing focusable inside get tabindex="0" and a name (a11y/scrollable-region-focusable).
  • Custom widgets (tabs, menus, listboxes) have one Tab stop and arrow keys inside, as the APG pattern says.
  • Act on click, not mousedown or touchstart; give drag interactions a click alternative (WCAG 2.5.2, 2.5.7).

Kroki, które wykonuje agent

  1. Start from native elements: button, a href, input, select, details, dialog. They are focusable and handle Enter and Space for free.
  2. For a custom widget, follow its APG pattern (fe-a11y-dialog, fe-a11y-menus, fe-a11y-tabs-accordion, fe-a11y-combobox): roving tabindex (0 on the current item, -1 on the rest) or aria-activedescendant.
  3. Style focus once, globally: :focus-visible { outline: 2px solid var(--focus); outline-offset: 2px; }; check it on every background.
  4. Put the skip link and scroll-padding-top in the shared layout; read the sticky header height from one custom property.
  5. When content appears after a trigger (a panel, an error summary, a deleted row's neighbour), insert it after the trigger in the DOM or move focus to it; never let focus fall to <body>.
  6. In an SPA, use the router's announcer (Next.js, SvelteKit, Nuxt <NuxtRouteAnnouncer>) and focus the h1 after navigation.

Jak agent sprawdza swoją pracę

  • npx github:dawidolko/frontend-skills audit --changed finds clickable divs, fake links, positive tabindex and removed outlines.
  • audit --url <page> adds axe-core results (skip link, scrollable regions).
  • By hand, for every change: unplug the mouse, Tab and Shift+Tab through the page; every control is reachable, visible when focused, works with Enter or Space, and Escape closes what it opened.
