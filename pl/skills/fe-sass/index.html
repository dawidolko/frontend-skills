Sass (SCSS)

Writes and reviews Sass (SCSS) for Dart Sass - the module system with @use and @forward, sass:math and sass:color, division, placeholders, the project's px-to-rem helper - and says when plain CSS now does the job. Use when editing .scss files or scss style blocks, removing @import or deprecation warnings, or asked to review Sass.

Reguły, których uczy

  • sass/no-import

    Load Sass files with @use and @forward, not @import, which is deprecated and will be removed in Dart Sass 3.

    umiarkowana statyczne

  • sass/no-global-builtins

    Call Sass built-in functions through their module (map.get, math.div, string.index) after @use "sass:...", not as globals.

    drobna statyczne

  • sass/no-legacy-color-functions

    Adjust colours with color.scale or color.adjust (and read channels with color.channel), not darken, lighten, fade-out and the like.

    drobna statyczne

  • sass/math-div

    Divide with math.div() in Sass; a slash between Sass values is becoming a list separator, as it is in CSS.

    drobna statyczne

  • sass/rem-helper

    Sizes are converted with the project's px-to-rem function, never by dividing by a hard-coded base by hand.

    drobna statyczne

  • css/rem-helper

    Font sizes and spacing use the project's px-to-rem helper (its rem function), not raw px.

    drobna statyczne

  • sass/no-extend-class

    Extend only placeholder selectors (%name), or use a mixin; @extend of a real class copies selectors everywhere it appears.

    drobna statyczne

  • sass/no-node-sass

    Compile Sass with Dart Sass (the sass or sass-embedded package), never node-sass, which is deprecated LibSass.

    umiarkowana statyczne

  • sass/custom-properties-for-themes

    Values that change at run time (themes, dark mode, user settings) are CSS custom properties; Sass variables are for build-time constants.

    drobna ręczne

Skrót reguł

Ta część jest kopiowana do zawężonego pliku reguł każdego agenta, więc musi być zrozumiała sama w sobie:

  • Load files with @use and re-export with @forward; never @import (sass/no-import).
  • Call built-ins through their modules: map.get, math.percentage, string.index (sass/no-global-builtins).
  • Change colours with color.scale or color.adjust, never darken, lighten or fade-out (sass/no-legacy-color-functions).
  • Divide with math.div(); a bare / between Sass values is deprecated (sass/math-div).
  • Write sizes with the project's px-to-rem function, never raw px (css/rem-helper) or a hand-made math.div(24px, 16px) * 1rem (sass/rem-helper).
  • @extend only %placeholders; otherwise use a mixin (sass/no-extend-class).
  • Compile with Dart Sass (sass or sass-embedded), never node-sass (sass/no-node-sass).
  • Themeable values are CSS custom properties; Sass variables are build-time constants (sass/custom-properties-for-themes).
  • Keep nesting shallow (about three levels) and put declarations before nested rules.

Kroki, które wykonuje agent

  1. Check the profile's helpers: with a rem-function, every size goes through it (rem-calc(24px)); with custom-properties or design-tokens, use those names instead of new variables.
  2. Structure: partials per concern (_tokens.scss, _functions.scss, _mixins.scss), an _index.scss that @forwards them, and @use 'abstracts' at the top of each file. Use namespaces (tokens.$space-4); as * only for a small file you own.
  3. Configure a library with @use 'lib' with ($primary: ...); give your own module's settings !default.
  4. Migrate a code base with the official tool: npx sass-migrator module --migrate-deps src/main.scss, then npx sass-migrator division 'src/**/*.scss'. Run the build and fix the remaining deprecation warnings, one kind at a time.
  5. Prefer plain CSS where it is now enough: native nesting, var(), color-mix(), clamp(), @layer and @container need no Sass. In a Tailwind 4 project, do not add Sass at all (tailwind/no-preprocessor).
  6. Plain CSS concerns (line height, !important, z-index, tokens) follow the fe-css-architecture skill.

Jak agent sprawdza swoją pracę

  • npx github:dawidolko/frontend-skills audit --changed reports @import, global built-ins, deprecated colour functions, slash division, sizes that bypass the rem helper, @extend of classes and node-sass.
  • Build once and read the warnings: Dart Sass names each deprecation (import, global-builtin, slash-div, color-functions); --fatal-deprecation=<name> in CI keeps a fixed one fixed.
  • Lint with stylelint-scss where the project uses Stylelint.
