Dostępność

Data tables

Builds data tables that screen readers can navigate and small screens can show (WCAG 2.2 AA as a target) - th with scope, captions, sortable headers with aria-sort, responsive scroll containers, and when a table should be a list or a grid. Use when rendering tabular data, a pricing or comparison table, a data grid or an admin list in any stack, or when asked "make this table accessible".

fe-a11y-tableskażdego projektu webowego5 regułładowane zawsze: 92 tokeny; przy użyciu: 864 tokeny; w referencjach na żądanie: 1043 tokeny.

Jak go używać

Po instalacji agent sam ładuje skill, gdy zadanie pasuje do jego opisu. Możesz też poprosić o niego własnymi słowami, na przykład:

Frazy z opisu skilla, po których agent go wybiera (po angielsku, jak w skillu):

  • make this table accessible

A żeby sprawdzić i poprawić pracę:

  • Użyj skilla fe-a11y-tables na tym pliku.
  • Uruchom audyt front-endu na moich zmianach i popraw wszystko, co poważne.
  • Wyjaśnij a11y/table-headers i popraw to tutaj.

Reguły, których uczy

  • a11y/table-headers

    Data tables mark their header cells with th (with scope when needed); layout tables carry role="presentation".

    poważnastatyczneWCAG 1.3.1

  • a11y/table-caption

    A data table has a name, from a caption element or aria-labelledby pointing at the heading above it.

    drobnaręczneWCAG 1.3.1

  • a11y/table-sort

    Sortable columns use a button inside the th, and aria-sort only on the header of the column that is sorted.

    umiarkowanaręczneWCAG 2.1.1, 4.1.2

  • a11y/scrollable-region-focusable

    A scrolling region with no focusable content inside can itself take focus (tabindex="0") and has a name.

    poważnaw przeglądarceWCAG 2.1.1

  • a11y/reflow

    At 320 CSS pixels wide (400% zoom) content reflows into one column with no horizontal scrolling, except tables, maps and similar.

    poważnaręczneWCAG 1.4.10

Skrót reguł

Ta część jest kopiowana do zawężonego pliku reguł każdego agenta, więc musi być zrozumiała sama w sobie:

  • Header cells are <th>, with scope="col" or scope="row"; never bold <td> (a11y/table-headers).
  • Every data table has a name: <caption> or aria-labelledby (a11y/table-caption).
  • Sortable headers hold a <button>; aria-sort is on the sorted column only (a11y/table-sort).
  • A wide table scrolls inside a container with tabindex="0", role="region" and a label (a11y/scrollable-region-focusable).
  • The page around it reflows at 320px; only the table scrolls (a11y/reflow).
  • Use a table for data with rows and columns, never for layout; layout tables get role="presentation".
  • Keep the native table semantics: do not set display: block or grid on table, tr or td without restoring roles.
  • Use role="grid" only for spreadsheet-like editing with arrow-key navigation; a list of records is a table.

Kroki, które wykonuje agent

  1. Check the table component or library first (TanStack Table renders your markup; AG Grid and MUI Data Grid have their own ARIA): fix headers and names at the component level.
  2. Write the skeleton: table > caption > thead with th scope="col" > tbody with a th scope="row" per row where a cell names the row.
  3. For complex headers (two header rows, merged cells), use id on each th and headers="…" on the tds, or split the table.
  4. For small screens, prefer a scroll container over turning rows into cards; if you do turn rows into cards, render a list or a dl, not a restyled table.
  5. Row actions: one named button per row ("Edit invoice 1042"), not an unnamed icon.

Jak agent sprawdza swoją pracę

  • npx github:dawidolko/frontend-skills audit --changed finds tables with data cells and no header cells, and unnamed icon buttons in rows.
  • audit --url <page> adds axe-core's header checks and the scrollable region check on the rendered table.
  • By hand: with a screen reader, move through cells with the table keys (Ctrl+Alt+arrows in NVDA and VoiceOver) and hear the headers; zoom to 400% and scroll the table alone.
