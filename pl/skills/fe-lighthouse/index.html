Wydajność

Lighthouse and PageSpeed

Runs and reads Lighthouse 13 for performance, accessibility, best practices and SEO - locally, in Chrome DevTools, PageSpeed Insights and CI with Lighthouse CI - and turns the report into fixes without chasing the score. Use when asked to run Lighthouse or PageSpeed, set up performance budgets or a CI gate, explain a score or an insight, or "get the page to green".

fe-lighthousekażdego projektu webowego6 regułładowane zawsze: 82 tokeny; przy użyciu: 820 tokenów; w referencjach na żądanie: 1485 tokenów.

Jak go używać

Po instalacji agent sam ładuje skill, gdy zadanie pasuje do jego opisu. Możesz też poprosić o niego własnymi słowami, na przykład:

Frazy z opisu skilla, po których agent go wybiera (po angielsku, jak w skillu):

  • get the page to green

A żeby sprawdzić i poprawić pracę:

  • Użyj skilla fe-lighthouse na tym pliku.
  • Uruchom audyt front-endu na moich zmianach i popraw wszystko, co poważne.
  • Wyjaśnij perf/lighthouse-ci i popraw to tutaj.

Reguły, których uczy

  • perf/lighthouse-ci

    Lighthouse in CI runs each URL several times, asserts on metrics and categories with realistic thresholds, and never demands a perfect 100.

    drobnaręczne

  • perf/field-data-p75

    Claims about Core Web Vitals come from field data at the 75th percentile, not from a Lighthouse score.

    drobnaręczne

  • tooling/console-clean

    Pages log no errors and use no deprecated browser APIs, as seen in the console on load and in the main flows.

    drobnaw przeglądarce

  • perf/lcp-image

    The LCP image is in the initial HTML, not lazy, and has fetchpriority="high"; a CSS background LCP image is preloaded.

    umiarkowanaw przeglądarce

  • perf/layout-shift

    Nothing moves after it appears - space is reserved for images, embeds, ads and late content (CLS 0.1 or less).

    umiarkowanaw przeglądarce

  • perf/code-split

    JavaScript is split by route, and features that most visits do not use load on demand with dynamic import().

    umiarkowanaw przeglądarce

Skrót reguł

Ta część jest kopiowana do zawężonego pliku reguł każdego agenta, więc musi być zrozumiała sama w sobie:

  • The performance score weights TBT 30, LCP 25, CLS 25, FCP 10, Speed Index 10; fix the heaviest failing metric first.
  • Run the mobile preset (the default) and --preset=desktop separately; report which one.
  • Run at least three times and use the median; never gate CI on one run or on 100 (perf/lighthouse-ci).
  • A lab score is not a Core Web Vitals result; vitals come from field data at p75 (perf/field-data-p75).
  • Lighthouse 13 shows insights (LCP discovery, layout shift culprits, render blocking, third parties) instead of the old opportunities; read them for causes (perf/lcp-image, perf/layout-shift, perf/code-split).
  • Accessibility 100 means no automated audit failed, not that the page is accessible; do the manual checks.
  • Keep the console free of errors and deprecated APIs (tooling/console-clean).
  • Test production builds on a quiet machine in a clean profile (no extensions), not the dev server.
  • Never optimise for the score by hiding content from Lighthouse or detecting its user agent.

Kroki, które wykonuje agent

  1. Build and serve the production output locally (npm run build then the framework's preview), or use the deployed URL.
  2. Run npx github:dawidolko/frontend-skills audit --url <url>: it runs Lighthouse and axe-core in the local Chrome (after a yes) and maps results to rule ids. Or run npx lighthouse@13.6.0 <url> --output=json --output-path=./lh.json --quiet.
  3. Read in order: metric values, then the insights for the failing metric, then diagnostics. Fix one cause, rebuild, rerun three times.
  4. For CI, add @lhci/cli with a lighthouserc.json: several URLs, numberOfRuns: 3, metric assertions, results kept as artefacts.
  5. Write results with the tool version, preset, number of runs and date.

Jak agent sprawdza swoją pracę

  • npx github:dawidolko/frontend-skills audit --url <url> gives the four category scores, the lab metrics and findings by rule id.
  • PageSpeed Insights (https://pagespeed.web.dev/) adds field data for public URLs with enough traffic.
  • Compare two runs with the Lighthouse viewer or lhci server only when both used the same preset and machine.
