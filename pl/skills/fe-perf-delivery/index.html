Wydajność

JavaScript, CSS and asset delivery

Ships less and earlier - JavaScript and CSS delivery, code splitting, hydration cost, third-party scripts and facades, resource hints, caching headers and modern browser targets - in any stack. Use when a bundle is large, a page loads many scripts, adding analytics, a widget or a dependency, setting cache headers, or when asked "why is this page heavy" or "reduce JavaScript".

fe-perf-deliverykażdego projektu webowego8 regułładowane zawsze: 81 tokenów; przy użyciu: 837 tokenów; w referencjach na żądanie: 1431 tokenów.

Jak go używać

Po instalacji agent sam ładuje skill, gdy zadanie pasuje do jego opisu. Możesz też poprosić o niego własnymi słowami, na przykład:

Frazy z opisu skilla, po których agent go wybiera (po angielsku, jak w skillu):

  • why is this page heavy
  • reduce JavaScript

A żeby sprawdzić i poprawić pracę:

  • Użyj skilla fe-perf-delivery na tym pliku.
  • Uruchom audyt front-endu na moich zmianach i popraw wszystko, co poważne.
  • Wyjaśnij perf/render-blocking-script i popraw to tutaj.

Reguły, których uczy

  • perf/render-blocking-script

    A script in the head loads with defer, async or type="module", never as a plain blocking script.

    umiarkowanastatyczne

  • perf/third-party-async

    Third-party scripts load with async or defer (or a framework strategy such as lazyOnload), never as parser-blocking tags.

    umiarkowanastatyczne

  • perf/css-no-import

    Shipped CSS does not chain stylesheets with @import; link them in the HTML or combine them in a build.

    umiarkowanastatyczne

  • perf/no-whole-library-import

    Client code does not import all of lodash or moment; use lodash-es, per-method imports, Intl or the platform.

    umiarkowanastatyczne

  • perf/code-split

    JavaScript is split by route, and features that most visits do not use load on demand with dynamic import().

    umiarkowanaw przeglądarce

  • perf/third-party-cost

    Each third-party script earns its place, loads late, and heavy embeds (video, maps, chat) start as a lightweight facade.

    umiarkowanaw przeglądarce

  • perf/cache-static-assets

    Content-hashed assets are cached for a year as immutable; HTML is revalidated (no-cache), never cached long.

    umiarkowanaw przeglądarce

  • perf/no-legacy-javascript

    Do not ship polyfills and down-level transforms for features your target browsers already support; declare targets once.

    drobnaw przeglądarce

Skrót reguł

Ta część jest kopiowana do zawężonego pliku reguł każdego agenta, więc musi być zrozumiała sama w sobie:

  • Head scripts use defer or type="module"; third-party scripts use async, defer or a framework strategy (perf/render-blocking-script, perf/third-party-async).
  • Shipped CSS never chains files with @import; link them or bundle them (perf/css-no-import).
  • Never import all of lodash or moment in client code; use lodash-es, per-method paths or Intl (perf/no-whole-library-import).
  • Split by route and load rare features with import() (perf/code-split).
  • Each third party has an owner and a reason, loads late, and heavy embeds start as a facade (perf/third-party-cost).
  • Hashed assets are cached a year as immutable; HTML is no-cache (perf/cache-static-assets).
  • Declare browser targets once; no blanket polyfills for Baseline features (perf/no-legacy-javascript).
  • Hydrate only what is interactive: server-render static parts, use islands or server components.
  • Preconnect to at most two or three critical origins; preload only late-discovered critical files.
  • Before adding a dependency, check its size and whether the platform already does it.

Kroki, które wykonuje agent

  1. Measure first: the build's bundle report (rollup-plugin-visualizer, @next/bundle-analyzer, Lighthouse treemap) and the network panel on a throttled mobile profile.
  2. Remove before you optimise: unused dependencies, duplicate libraries, dead routes, polyfills for old browsers.
  3. Move work off the critical path: defer scripts, lazy routes and dialogs, client:visible or @defer for below-the-fold widgets.
  4. Shrink what stays: tree-shakable imports, modern targets, Brotli compression on the host, small critical CSS.
  5. Set caching once in the host configuration, and verify the response headers of a deployed page.

Jak agent sprawdza swoją pracę

  • npx github:dawidolko/frontend-skills audit --changed finds blocking head and third-party scripts, CSS @import chains in plain sites and whole-library imports.
  • audit --url <page> maps Lighthouse's unused JavaScript, third parties, cache lifetimes and legacy JavaScript results to these rule ids.
  • By hand: compare the bundle report before and after a change; a new dependency over ~20 kB gzip needs a reason in the pull request.
