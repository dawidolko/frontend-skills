Dostępność

ARIA, names and live regions

Gets names, roles, states and announcements right in any stack to WCAG 2.2 AA as a target - native elements before ARIA, accessible names for icon buttons and links, valid roles and aria-* attributes, aria-hidden used safely, state attributes, live regions for status messages. Use when adding ARIA, building a custom control or toast, labelling icons, or when asked "what will a screen reader say".

fe-a11y-ariakażdego projektu webowego8 regułładowane zawsze: 91 tokenów; przy użyciu: 1070 tokenów; w referencjach na żądanie: 1372 tokeny.

Jak go używać

Po instalacji agent sam ładuje skill, gdy zadanie pasuje do jego opisu. Możesz też poprosić o niego własnymi słowami, na przykład:

Frazy z opisu skilla, po których agent go wybiera (po angielsku, jak w skillu):

  • what will a screen reader say

A żeby sprawdzić i poprawić pracę:

  • Użyj skilla fe-a11y-aria na tym pliku.
  • Uruchom audyt front-endu na moich zmianach i popraw wszystko, co poważne.
  • Wyjaśnij a11y/control-name i popraw to tutaj.

Reguły, których uczy

  • a11y/control-name

    Every button and link has an accessible name; icon-only controls get visually hidden text or aria-label.

    krytycznastatyczneWCAG 4.1.2, 2.4.4

  • a11y/prefer-native-element

    Use the native element instead of a role it already provides (button, a href, input, h1–h6, nav, main, ul, li).

    drobnastatyczneWCAG 4.1.2

  • a11y/aria-valid

    Every role value is a real WAI-ARIA role and every aria-* attribute name exists (aria-labelledby, not aria-labeledby).

    poważnastatyczneWCAG 4.1.2

  • a11y/aria-hidden-focusable

    aria-hidden="true" is never on a focusable element or on an element that contains one.

    poważnastatyczneWCAG 4.1.2

  • a11y/aria-label-generic

    aria-label and aria-labelledby go on controls, landmarks and named roles, never on a plain div, span or p.

    poważnastatyczneWCAG 4.1.2

  • a11y/aria-ref-exists

    Ids named in aria-labelledby, aria-describedby and aria-errormessage exist in the page and are unique.

    poważnastatyczneWCAG 1.3.1, 4.1.2

  • a11y/state-exposed

    Custom toggles, disclosures and selections expose their state (aria-expanded, aria-pressed, aria-checked, aria-selected).

    poważnaręczneWCAG 4.1.2

  • a11y/status-message-live

    Messages that appear without moving focus (saved, results, errors, progress) are announced through a live region.

    poważnaręczneWCAG 4.1.3

Skrót reguł

Ta część jest kopiowana do zawężonego pliku reguł każdego agenta, więc musi być zrozumiała sama w sobie:

  • Every button and link has a name; icon-only controls get hidden text or aria-label, the icon aria-hidden="true" (a11y/control-name).
  • Use the native element before a role: <button>, <a href>, <input type="checkbox">, <nav>, <h2> (a11y/prefer-native-element).
  • Roles and aria-* names must exist in WAI-ARIA 1.2: aria-labelledby, never aria-labeledby (a11y/aria-valid).
  • Never aria-hidden="true" on anything focusable or around it; use inert or hidden (a11y/aria-hidden-focusable).
  • Never aria-label on a plain div, span or p; label the control or give a fitting role (a11y/aria-label-generic).
  • Ids in aria-labelledby and aria-describedby exist once on the page; generate them with useId() (a11y/aria-ref-exists).
  • Custom toggles expose state: aria-expanded, aria-pressed, aria-checked, aria-selected, aria-current (a11y/state-exposed).
  • Status messages go into a live region that exists before the text: role="status", role="alert" only for urgent errors (a11y/status-message-live).
  • The accessible name contains the visible label, best at its start (WCAG 2.5.3); never replace visible words with different ones.
  • Never put ARIA on an element to change its look; ARIA changes only what is announced.

Kroki, które wykonuje agent

  1. Ask first: is there a native element? dialog, details, select, input type="range", progress, meter, search. Use it and stop.
  2. When there is none, follow the APG pattern for the widget (role, required children, states, keys) and the skills fe-a11y-dialog, fe-a11y-menus, fe-a11y-tabs-accordion, fe-a11y-combobox.
  3. Name things in this order: visible text, aria-labelledby to visible text, aria-label, and never title or placeholder alone.
  4. Bind every state attribute to the same variable that drives the visual state, so they cannot drift apart.
  5. For async results, keep one polite live region per page area (<p role="status">) in the layout; write text into it; clear it after a few seconds only if the text stays visible elsewhere.

Jak agent sprawdza swoją pracę

  • npx github:dawidolko/frontend-skills audit --changed finds unnamed icon buttons and links, invalid roles and attributes, aria-hidden over focusable content, labels on generic elements and broken id references.
  • audit --url <page> adds axe-core's name and ARIA rules on the rendered page, where names that come from components are known.
  • By hand: listen with a screen reader (VoiceOver, NVDA) to each changed control and message: name, role, state, and the announcement after an action.
