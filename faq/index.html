Questions and answers

Is it free?

Yes. The code, the skills and the rules are under the MIT licence. There is no account, no paid plan and nothing to sign up for.

Does it send my code anywhere?

No. The tool has no telemetry and makes no network call unless you start one: npx fetches the tool from GitHub, and audit --url asks before it fetches Lighthouse and axe-core and opens only the address you pass.

Which agents does it support?

Claude Code, OpenAI Codex, Cursor, GitHub Copilot, Gemini CLI, Antigravity CLI, Devin / Windsurf, OpenCode, Cline, Zed, JetBrains Junie, Kiro, Augment, Trae, Continue, Amazon Q Developer, Aider. What each one reads, with links to its documentation, is in docs/agents.md.

Will it make my site WCAG compliant?

No tool can. The rules cite WCAG 2.2 success criteria and the audit finds problems a machine can see, but only part of them. Meaning, reading order and many keyboard and screen reader issues need a person; the report lists them as a checklist.

Will it overwrite my AGENTS.md or CLAUDE.md?

No. It adds one block between marker comments and never touches the text around it. Files it creates and files it changes are recorded, and --dry-run shows everything before it writes.

How do I remove it?

Run npx github:dawidolko/frontend-skills uninstall. It removes the files it wrote while they are unchanged, removes its blocks from shared files and keeps anything you edited.

How many tokens does it cost?

An agent always loads only the names and descriptions of the installed skills; the rest loads when a task needs it. frontend-skills tokens prints the numbers for your project; the measured cost of every skill is on the How it works page.

My project has its own helpers. Will the rules fight them?

No. A rem function, generated icon classes, design tokens or custom properties are detected and recorded in the profile, and the rules that depend on them tell the agent to use your helper. You can correct or add one in the profile.

Can I switch a rule off?

Yes: fs-ignore <rule id> in a comment on the line or the line above, or audit.ignore and audit.exclude in .frontend-skills/profile.json.

Does it work in a monorepo?

Yes. Workspaces from npm, pnpm, Yarn, Lerna, Nx and Turborepo are read, each package gets its own entry in the profile, and the skills match the union of their stacks.

Why does it run from GitHub and not from npm?

So that it needs no install step: npx github:dawidolko/frontend-skills runs the repository as it is, with Node.js 20 or newer and no dependencies.

How can I add a rule or a skill?

The authoring guide in docs/authoring.md describes the format, the checks and the tests. Issues and pull requests on GitHub are welcome.
