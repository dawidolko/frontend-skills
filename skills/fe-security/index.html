Quality

Front-end security

Keeps front-end code from opening security holes in any stack - XSS sinks (innerHTML, dangerouslySetInnerHTML, v-html, {@html}) and sanitizing, no eval, postMessage origins, secrets kept out of public env variables, CSP and HTTP-only headers, SRI, window.open, HTTPS. Use when rendering user or CMS content, embedding third parties, adding env variables or headers, or when asked "is this safe".

How to use it

Once installed, the agent loads the skill by itself when a task matches its description. You can also ask for it in your own words, for example:

Phrases from the skill description that make the agent pick it:

  • is this safe

And to check and fix the work:

  • Use the fe-security skill on this file.
  • Run the front-end audit on what I changed and fix everything serious.
  • Explain security/raw-html-sink and fix it here.

Rules it teaches

  • security/raw-html-sink

    Never pass user or remote data to a raw HTML sink (innerHTML, dangerouslySetInnerHTML, v-html, {@html}) without sanitizing it.

    seriousstatic

  • security/no-eval

    Front-end code never runs strings as code - no eval, new Function or string arguments to setTimeout and setInterval.

    seriousstatic

  • security/postmessage-origin

    postMessage names an exact target origin, and every window message listener checks event.origin against an allowlist.

    seriousstatic

  • security/no-secrets-in-client-env

    Secrets never use a client-exposed environment prefix (NEXT_PUBLIC_, VITE_, PUBLIC_, NUXT_PUBLIC_); they stay on the server.

    criticalstatic

  • security/sri-cdn

    Versioned files from a public CDN carry Subresource Integrity (integrity plus crossorigin), or are self-hosted.

    moderatestatic

  • security/window-open-noopener

    window.open for another site passes "noopener" (and "noreferrer" when needed) so the new page cannot control yours.

    minorstatic

  • security/csp-meta-ignored

    frame-ancestors, report-uri, sandbox and X-Frame-Options are sent as HTTP headers; in a meta tag they do nothing.

    moderatestatic

  • security/csp-strict

    Production pages send a strict Content Security Policy (nonces or hashes with strict-dynamic, object-src none, base-uri none).

    moderatebrowser

  • security/https-only

    Every page and every resource it loads use HTTPS; no mixed content and no http:// links to your own site.

    seriousbrowser

The rule digest

This part is copied into each agent's scoped rule file, so it stands on its own:

  • Never pass user, CMS or API data to a raw HTML sink unsanitized; render text, or sanitize with DOMPurify (security/raw-html-sink).
  • Never run strings as code: no eval, new Function, string timers (security/no-eval).
  • postMessage names an exact origin; window message listeners check event.origin (security/postmessage-origin).
  • Secrets never use a public env prefix (NEXT_PUBLIC_, VITE_, PUBLIC_); they stay in server code (security/no-secrets-in-client-env).
  • Versioned CDN files carry integrity and crossorigin, or are self-hosted (security/sri-cdn).
  • window.open to other sites passes noopener,noreferrer (security/window-open-noopener).
  • frame-ancestors, X-Frame-Options, HSTS and CSP reporting are HTTP headers, never meta tags (security/csp-meta-ignored).
  • Production sends a strict CSP with nonces or hashes (security/csp-strict); everything loads over HTTPS (security/https-only).
  • Validate URLs before binding them to href or src: allow https:, http:, mailto:, tel: only.
  • Auth cookies are set by the server with Secure, HttpOnly and SameSite; never write tokens into the DOM or URLs.
  • Never say code "is secure"; say what was checked and what a person must review.

Steps the agent follows

  1. Search the change for sinks: innerHTML, outerHTML, insertAdjacentHTML, document.write, dangerouslySetInnerHTML, v-html, {@html}, set:html, bypassSecurityTrust. For each, trace where the value comes from.
  2. For rich text from a CMS or Markdown, sanitize once at a single helper (DOMPurify, configured once), and use only that helper.
  3. For new environment variables, decide server or browser first; give browser ones the framework prefix only if they are meant to be public.
  4. For a new third party: self-host or pin with SRI, load it async, list it in the CSP, and isolate untrusted HTML in a sandboxed iframe.
  5. Set security headers in the host configuration (_headers, vercel.json, next.config headers(), middleware), and verify them on the deployed response.

How the agent checks the work

  • npx github:dawidolko/frontend-skills audit --changed finds unsanitized HTML sinks, eval, unchecked postMessage, secret-looking public env variables, CDN files without SRI, window.open without noopener and headers placed in meta tags.
  • audit --url <page> adds Lighthouse's HTTPS and CSP checks on the rendered page.
  • Run the package manager's audit (npm audit --audit-level=high) in CI. A person reviews authentication, authorisation, data flows and server configuration.
