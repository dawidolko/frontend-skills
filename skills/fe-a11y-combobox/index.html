Accessibility

Combobox, listbox and custom select

Builds autocomplete inputs, searchable selects, select-only comboboxes and listboxes that work with keyboard and screen readers (WAI-ARIA APG Combobox and Listbox patterns), after checking whether a native select or datalist is enough. Use when building a typeahead, search suggestions, a custom select, a tag or recipient picker, or when asked "make this dropdown accessible".

fe-a11y-comboboxevery web project6 rules82 tokens always loaded, 872 tokens when used, 1167 tokens in references on demand.

How to use it

Once installed, the agent loads the skill by itself when a task matches its description. You can also ask for it in your own words, for example:

Phrases from the skill description that make the agent pick it:

  • make this dropdown accessible

And to check and fix the work:

  • Use the fe-a11y-combobox skill on this file.
  • Run the front-end audit on what I changed and fix everything serious.
  • Explain a11y/combobox-on-input and fix it here.

Rules it teaches

  • a11y/combobox-on-input

    role="combobox" sits on the input itself (ARIA 1.2), not on a wrapper element that contains the input.

    seriousstaticWCAG 4.1.2

  • a11y/popup-button-expanded

    A control that opens a popup (aria-haspopup or role="combobox") has aria-expanded that follows the open state.

    seriousstaticWCAG 4.1.2

  • a11y/option-no-interactive

    Options in a listbox or combobox popup hold only text and images, never links, buttons or fields.

    seriousstaticWCAG 4.1.2

  • a11y/combobox-keyboard

    A combobox keeps focus in the input, marks the highlighted option with aria-activedescendant and supports Down, Up, Enter and Escape.

    seriousmanualWCAG 2.1.1, 4.1.2

  • a11y/input-label

    Every form field has a programmatic label (label element, aria-label or aria-labelledby); a placeholder is not a label.

    criticalstaticWCAG 1.3.1, 3.3.2, 4.1.2

  • a11y/status-message-live

    Messages that appear without moving focus (saved, results, errors, progress) are announced through a live region.

    seriousmanualWCAG 4.1.3

The rule digest

This part is copied into each agent's scoped rule file, so it stands on its own:

  • Use a native <select> (or <input list> with <datalist>) unless filtering, rich options or async search are really needed.
  • role="combobox" goes on the <input> itself, not on a wrapper (a11y/combobox-on-input).
  • The combobox has aria-expanded, aria-controls pointing at the listbox, and aria-autocomplete (a11y/popup-button-expanded).
  • Focus stays in the input; the highlighted option is aria-activedescendant with aria-selected="true" (a11y/combobox-keyboard).
  • Down, Up, Enter, Escape and Alt+Down work as the APG pattern says (a11y/combobox-keyboard).
  • Options hold only text and images, never buttons or links (a11y/option-no-interactive).
  • The input has a visible <label>; a placeholder is not a label (a11y/input-label).
  • Announce the result count in a polite live region after typing pauses (a11y/status-message-live).
  • Options have unique ids, and the list does not close when the pointer moves over it.

Steps the agent follows

  1. Try the native element first: <select> (styleable with appearance: base-select in Chromium as an enhancement only), or <datalist> for simple suggestions.
  2. Prefer a tested primitive from the project's library (React Aria ComboBox, Downshift, Radix Select, Reka UI Combobox, bits-ui Combobox, Angular CDK Listbox) over hand-written code.
  3. When writing one: label + input (role="combobox") + ul role="listbox" with li role="option" id; one state object holds open, activeIndex, options.
  4. Debounce async search, cancel stale requests, keep the highlight valid when results change, and announce "5 results" or "No results".
  5. For multi-select with chips, keep chip remove buttons outside the listbox and give each a name ("Remove Anna").

How the agent checks the work

  • npx github:dawidolko/frontend-skills audit --changed finds wrapper comboboxes, comboboxes without aria-expanded, controls inside options and unlabeled inputs.
  • By hand: type, arrow through suggestions, accept with Enter, close with Escape; with a screen reader hear the label, "expanded", the highlighted option and the result count.
