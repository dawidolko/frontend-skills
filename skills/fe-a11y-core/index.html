Accessibility

Accessibility, WCAG 2.2 map

The entry point for accessibility in any front-end stack - WCAG 2.2 A and AA mapped to code, the page basics (language, title, landmarks, iframes, timing), what automated checks find and what needs a person, and which accessibility skill to load next. Use when starting accessibility work, auditing a page or a component library, or when asked "is this accessible" or "WCAG".

How to use it

Once installed, the agent loads the skill by itself when a task matches its description. You can also ask for it in your own words, for example:

Phrases from the skill description that make the agent pick it:

  • is this accessible
  • WCAG

And to check and fix the work:

  • Use the fe-a11y-core skill on this file.
  • Run the front-end audit on what I changed and fix everything serious.
  • Explain a11y/lang-valid and fix it here.

Rules it teaches

  • a11y/lang-valid

    Every lang value is a valid BCP 47 language tag ("en", "en-GB", "pl"), never "en_US" or a language name.

    seriousstaticWCAG 3.1.1, 3.1.2

  • a11y/no-meta-refresh

    No meta refresh reloads or redirects the page after a delay; redirect on the server or let people choose.

    seriousstaticWCAG 2.2.1

  • a11y/iframe-title

    Every visible iframe has a title that says what it contains (map, video, payment form).

    seriousstaticWCAG 4.1.2

  • a11y/landmarks

    Each page has one main landmark, all content sits inside landmarks, and repeated landmarks of a kind have distinct labels.

    moderatebrowserWCAG 1.3.1, 2.4.1

  • a11y/html-lang

    The html element names the language of the page in a non-empty lang attribute.

    seriousstaticWCAG 3.1.1

  • a11y/page-title

    Every HTML document has a title element that says what the page is about.

    seriousstaticWCAG 2.4.2

  • a11y/img-alt

    Every img and area element has an alt attribute; a decorative image has alt="".

    criticalstaticWCAG 1.1.1

  • a11y/control-name

    Every button and link has an accessible name; icon-only controls get visually hidden text or aria-label.

    criticalstaticWCAG 4.1.2, 2.4.4

  • a11y/input-label

    Every form field has a programmatic label (label element, aria-label or aria-labelledby); a placeholder is not a label.

    criticalstaticWCAG 1.3.1, 3.3.2, 4.1.2

  • a11y/no-click-on-static

    A click handler belongs on a button or link; a static element with one also needs a role, tabindex and a key handler.

    seriousstaticWCAG 2.1.1, 4.1.2

  • a11y/focus-visible

    Never remove the focus outline without drawing a visible replacement for keyboard focus.

    seriousstaticWCAG 2.4.7

  • a11y/color-contrast

    Text has a contrast ratio of at least 4.5:1 with its background; large text (24px, or 18.5px bold) at least 3:1.

    seriousbrowserWCAG 1.4.3

The rule digest

This part is copied into each agent's scoped rule file, so it stands on its own:

  • Work to WCAG 2.2 level AA as the target; say "helps you work to WCAG 2.2 AA", never "compliant" or "accessible".
  • Use native HTML first; add ARIA only where no element does the job.
  • <html lang> is set and every lang value is a valid tag (a11y/html-lang, a11y/lang-valid).
  • Every page and route has a unique <title>; the layout has one <main> and labelled landmarks (a11y/page-title, a11y/landmarks).
  • Images have alt, buttons and links have names, fields have labels (a11y/img-alt, a11y/control-name, a11y/input-label).
  • Everything works with the keyboard and shows where focus is (a11y/no-click-on-static, a11y/focus-visible).
  • Text contrast is at least 4.5:1, large text 3:1 (a11y/color-contrast).
  • Every iframe has a title (a11y/iframe-title).
  • No timed refresh or redirect; time limits can be turned off or extended (a11y/no-meta-refresh).
  • Report results as "N problems found, M items need a person", never as a pass.

Steps the agent follows

  1. Load the skill for the work at hand: forms fe-a11y-forms, keyboard and focus fe-a11y-keyboard, names and live regions fe-a11y-aria, colour and layout fe-a11y-visual, media fe-a11y-media, widgets fe-a11y-dialog, fe-a11y-menus, fe-a11y-tabs-accordion, fe-a11y-combobox, fe-a11y-carousel-toast, fe-a11y-tables.
  2. Fix the shared layout first (document shell, skip link, landmarks, focus style, live region): one change fixes every page.
  3. Fix shared components next (button, link, field, dialog, icon): find them through the profile and lessons.
  4. Run the static audit on the changed files, then the page audit on a running page, then the manual checks for the criteria that tools do not cover.
  5. Record decisions that the next person needs (for example "icons come from <Icon>, which sets aria-hidden") with learn --lesson.

How the agent checks the work

  • npx github:dawidolko/frontend-skills audit --changed runs the static rules; audit --url <page> adds axe-core and Lighthouse on the rendered page.
  • Automated checks find only part of the problems: about half of the A and AA criteria have no automated rule at all. The manual list in the reference covers the rest.
  • By hand on every change: keyboard only, screen reader on the changed part, zoom to 400%.
