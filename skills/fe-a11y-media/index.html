Accessibility

Media, motion and flashing

Makes audio, video and moving content usable to WCAG 2.2 AA as a target - captions with track, transcripts, audio description, no autoplaying sound, pause controls for anything that moves or loops, no flashing, reduced motion. Use when adding a video or audio player, a background video, an animated hero, a GIF or a ticker, or when asked "does this video need captions".

fe-a11y-mediaevery web project5 rules88 tokens always loaded, 781 tokens when used, 1342 tokens in references on demand.

How to use it

Once installed, the agent loads the skill by itself when a task matches its description. You can also ask for it in your own words, for example:

Phrases from the skill description that make the agent pick it:

  • does this video need captions

And to check and fix the work:

  • Use the fe-a11y-media skill on this file.
  • Run the front-end audit on what I changed and fix everything serious.
  • Explain a11y/video-captions and fix it here.

Rules it teaches

  • a11y/video-captions

    Recorded video with speech or meaningful sound has synchronised captions, for example a <track kind="captions">.

    criticalstaticWCAG 1.2.2

  • a11y/media-alternative

    Recorded audio has a transcript; recorded video has audio description of what is only shown, or a full text alternative.

    seriousmanualWCAG 1.2.1, 1.2.3, 1.2.5

  • a11y/no-autoplay-audio

    No audio plays automatically; autoplaying video is muted, and any sound longer than 3 seconds can be paused or stopped.

    moderatestaticWCAG 1.4.2

  • a11y/pause-auto-motion

    Anything that moves, blinks, scrolls or updates by itself for more than 5 seconds has a visible pause or stop control.

    seriousmanualWCAG 2.2.2

  • a11y/no-flash

    Nothing flashes more than three times in any one second, unless the flash is small and below the general and red thresholds.

    criticalmanualWCAG 2.3.1

The rule digest

This part is copied into each agent's scoped rule file, so it stands on its own:

  • Recorded video with speech has captions: <track kind="captions" src="….vtt" srclang default> (a11y/video-captions).
  • Recorded audio has a transcript next to it; video has audio description or a full text alternative (a11y/media-alternative).
  • Nothing plays sound by itself; an autoplaying video is muted and playsinline (a11y/no-autoplay-audio).
  • Anything that moves, loops or auto-updates for over 5 seconds has a visible pause control (a11y/pause-auto-motion).
  • Nothing flashes more than three times a second (a11y/no-flash).
  • Players show native controls or a custom control bar of real <button>s with names and states.
  • Start non-essential motion only inside @media (prefers-reduced-motion: no-preference).
  • Never <marquee> or <blink>; never an animated GIF longer than 5 seconds without a way to stop it.

Steps the agent follows

  1. Find the player: a native <video>, a library (Video.js, Plyr, Vidstack), or an embed (YouTube, Vimeo). Check that captions and keyboard controls are switched on in its configuration.
  2. Store captions as WebVTT beside the media file; name it <file>.<lang>.vtt; add one <track> per language.
  3. Put the transcript link right under the player, as HTML.
  4. For background video: autoplay muted loop playsinline, a pause button, and no autoplay under reduced motion.
  5. Replace large GIFs with <video autoplay muted loop playsinline> plus a pause control (smaller files and pausable).

How the agent checks the work

  • npx github:dawidolko/frontend-skills audit --changed finds videos without a captions track and media that autoplays with sound.
  • By hand: play with sound off (captions readable and in sync), with the screen off (transcript or description is enough), with the keyboard only, and with reduced motion turned on in the OS.
