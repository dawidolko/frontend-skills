Icons

Uses and builds icons the way the project does - one icon set generated by the build from a folder of SVG files (sprite, icon classes or an Icon component per framework), currentColor sizing, decorative vs meaningful icons - and never a hard-coded icon file path. Use when adding or changing an icon, an icon button, an SVG sprite or icon font, or setting up icons in a new project.

Rules it teaches

  • html/icon-from-set

    When the project has an icon set (sprite, icon classes or an Icon component), markup uses it, never a hard-coded path to an icon file.

    minor static

  • html/project-icons

    Icons use the project's generated icon classes (its icon classes), not separate SVG image files.

    minor static

  • js/asset-import

    In a bundled project, images, fonts and media in component markup are imported or use the base-path helper, not hard-coded root paths.

    moderate static

  • a11y/img-alt

    Every img and area element has an alt attribute; a decorative image has alt="".

    critical static

The rule digest

This part is copied into each agent's scoped rule file, so it stands on its own:

  • Use the project's icon set: its generated classes (html/project-icons), its component or a <use href="#id"> of its sprite (html/icon-from-set).
  • Never hard-code a path to an icon file (<img src="/icons/x.svg">, sprite.svg#x) in markup; in CSS, no url() to an icon file (css/icon-from-set).
  • Add an icon by putting its SVG in the set's source folder and rebuilding; never copy it into public/.
  • One source folder, one generator, one naming scheme (close, chevron-down): no second set beside it.
  • Icons draw in currentColor and size in em or a size token, so they follow the text.
  • A decorative icon next to text gets aria-hidden="true"; an icon-only button or link gets its name on the button (aria-label or visually hidden text).
  • An icon shown with <img> has alt: empty for decoration, the meaning otherwise (a11y/img-alt).
  • Other images and media go through the bundler, not root paths (js/asset-import).

Steps the agent follows

  1. Find the set: helpers in the profile (icon-classes, icon-sprite); if it is missing, run npx github:dawidolko/frontend-skills learn and confirm what it finds with the person; an Icon component it does not detect goes into lessons.md as a convention.
  2. Use it the framework's way: React or Preact <Icon name="close" /> over a sprite or SVGR imports; Vue <SvgIcon name="close" /> (vite-plugin-svg-icons) or ~icons/ components (unplugin-icons); Svelte <Icon name="close" />; Angular <mat-icon svgIcon="close"> with MatIconRegistry; Astro <Icon name="close" /> from astro-icon/components (SVGs in src/icons/); plain sites a sprite <use href="#icon-close"> or the generated classes.
  3. No set yet: create one from src/icons/*.svg with the build (sprite plugin or unplugin-icons custom collection) and one small Icon component; remove fixed fill and width/height from the SVG files so the component controls them.
  4. Icon-only controls: <button type="button" aria-label="Close"><Icon name="close" aria-hidden="true" /></button>; touch targets at least 24 by 24 CSS px.

How the agent checks the work

  • npx github:dawidolko/frontend-skills audit --changed reports hard-coded icon files in markup where the project has a set, images without alt and hard-coded asset paths.
  • After a build, the sprite or icon CSS has a content hash in its file name and every icon you added is in it.
  • With a screen reader or the accessibility tree, an icon-only button reads its name once, not "image" or the file name.
