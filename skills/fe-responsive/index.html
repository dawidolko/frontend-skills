Foundations

Responsive design

Makes pages and components work from 320 CSS px phones to wide screens and at 400% zoom - viewport meta, fluid type and space, content breakpoints and container queries, no fixed wide boxes, dvh units, touch targets, no hover-only content, orientation and print. Use when building or fixing a layout for mobile, or asked "make this responsive", "it breaks on mobile", "it scrolls sideways".

fe-responsiveevery web project9 rules93 tokens always loaded, 1080 tokens when used, 1971 tokens in references on demand.

How to use it

Once installed, the agent loads the skill by itself when a task matches its description. You can also ask for it in your own words, for example:

Phrases from the skill description that make the agent pick it:

  • make this responsive
  • it breaks on mobile
  • it scrolls sideways

And to check and fix the work:

  • Use the fe-responsive skill on this file.
  • Run the front-end audit on what I changed and fix everything serious.
  • Explain responsive/viewport-meta and fix it here.

Rules it teaches

  • responsive/viewport-meta

    Every HTML document has <meta name="viewport" content="width=device-width, initial-scale=1">.

    seriousstatic

  • a11y/zoom-not-blocked

    The viewport never disables zoom (no user-scalable=no, no maximum-scale below 2).

    criticalstaticWCAG 1.4.4

  • responsive/dynamic-viewport-units

    A full-height layout uses 100dvh (or svh) instead of 100vh, which is taller than the visible area on mobile.

    minorstatic

  • responsive/no-viewport-font-size

    Text is never sized with viewport units alone (font-size 5vw); fluid type mixes in rem, as in clamp(1rem, 0.9rem + 1vw, 1.5rem).

    seriousstaticWCAG 1.4.4

  • responsive/no-fixed-wide-width

    No layout box gets a fixed width wider than 320 CSS px; cap it with max-width or min(100%, …) so the page reflows on narrow screens.

    seriousstaticWCAG 1.4.10

  • responsive/no-hover-only

    Nothing is revealed on hover alone; content and controls shown on hover also show on keyboard focus and are reachable on touch.

    seriousstaticWCAG 2.1.1

  • responsive/reflow

    The page reads without sideways scrolling at 320 CSS px and 400% zoom; only tables, maps and similar may scroll both ways.

    seriousmanualWCAG 1.4.10

  • responsive/orientation

    The page works in portrait and landscape; it never locks the orientation or asks people to rotate unless one orientation is essential.

    seriousmanualWCAG 1.3.4

  • css/rem-units

    Font sizes are written in rem (or em), never px, in projects without a rem helper; with one, css/rem-helper applies.

    minorstatic

The rule digest

This part is copied into each agent's scoped rule file, so it stands on its own:

  • Every document has <meta name="viewport" content="width=device-width, initial-scale=1"> (responsive/viewport-meta).
  • Never block zoom: no user-scalable=no, no maximum-scale below 2 (a11y/zoom-not-blocked).
  • Write the narrow layout first and widen it with min-width queries placed where the content breaks, in em, not device widths.
  • Components react to their slot with @container; media queries are for page regions.
  • No box wider than 320 CSS px without a cap: max-width or min(100%, …) (responsive/no-fixed-wide-width).
  • Fluid type mixes rem into the formula, clamp(1rem, 0.9rem + 1vw, 1.5rem), never viewport units alone (responsive/no-viewport-font-size).
  • Font sizes in rem (the project's helper when it has one) (css/rem-units).
  • Full-height sections use min-height: 100svh or 100dvh, not 100vh (responsive/dynamic-viewport-units).
  • Pointer targets are at least 24×24 CSS px, primary touch controls about 44×44.
  • Nothing is revealed on hover alone: show it on :focus-within and make it reachable on touch (responsive/no-hover-only).
  • The page reads at 320 CSS px and 400% zoom without sideways scrolling, in both orientations (responsive/reflow, responsive/orientation).

Steps the agent follows

  1. Fix the document shell once (root layout, index.html, app.html): viewport meta, no zoom block. Frameworks such as Next.js add a viewport tag; check the rendered HTML.
  2. Set base styles for the narrowest screen; add @media (width >= 48em) steps only where the content needs them, and @container for components.
  3. Make media fluid: img, video, iframe { max-width: 100%; height: auto; }, aspect-ratio for embeds, wide tables in a scrolling wrapper.
  4. Size type and space with rem and clamp(); give long strings overflow-wrap: anywhere.
  5. Give touch targets padding rather than larger icons; enlarge under (any-pointer: coarse), never shrink under fine.
  6. Add @media print for content people print: hide navigation, show link URLs where useful.

How the agent checks the work

  • npx github:dawidolko/frontend-skills audit --changed reports a missing or wrong viewport, blocked zoom, 100vh, viewport-only font sizes, fixed wide boxes and hover-only content.
  • audit --url <page> adds Lighthouse and axe results (meta-viewport, target-size).
  • By hand: DevTools device mode at 320×640 and 640×320, browser zoom 200% and 400%, Tab through every control, try the menu on a touch device.
